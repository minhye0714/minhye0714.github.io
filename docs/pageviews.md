# 글별 조회수

글 상단 작성자·읽기 시간 옆에 `조회수 N회`를 표시합니다. 기존 Cloudflare Worker와 D1을 공유하므로 새 분석 서비스 가입이나 인증키가 필요하지 않습니다. 집계는 기능을 운영에 반영한 시점부터 시작하며 과거 조회수는 복원하지 않습니다.

## 집계 방식

- 글을 실제로 표시한 시점에 해당 글의 누적 조회수를 올립니다. 목록·카테고리 화면을 열어도 글 조회수는 올라가지 않습니다.
- 같은 브라우저의 같은 글은 30분 동안 같은 임의 조회 ID를 사용하여 새로고침을 중복 집계하지 않습니다. 저장된 ID는 새 탭과 네트워크 재시도에도 재사용합니다. 최초 방문 시 여러 탭을 동시에 열면 브라우저 저장 시점에 따라 각각 집계될 수 있습니다.
- 조회 ID는 글별로 분리되고 브라우저에 저장됩니다. 서버는 조회 ID·글 주소·시각과 글별 누적 수를 저장하며 원본 IP나 브라우저 프로필을 저장하지 않습니다. 중복 방지용 ID는 하루 뒤 정리하지만 누적 수는 유지합니다.
- 집계 요청은 기존 출처 제한과 별도의 분당 60회 제한을 적용합니다. 댓글 작성·삭제 제한과는 분리합니다.
- 브라우저 저장소 차단, Do Not Track 또는 Global Privacy Control이 설정된 경우에는 조회수만 읽고 집계하지 않습니다.
- 서버에 연결되지 않으면 `—`를 표시합니다. 임의의 숫자를 실제 조회수처럼 표시하지 않습니다.

## 설정

`_config.yml`의 `pageviews.provider: worker`로 켭니다. API 주소는 `pageviews.endpoint`에 지정하거나 기본값인 `comments.anonymous.endpoint`를 공유합니다. `analytics.cloudflare`의 Cloudflare Web Analytics 설정과는 별개의 단순 조회수 기능입니다.

`GET /pageviews?post=/posts/글주소/`는 조회수만 읽습니다. `POST /pageviews`의 JSON 본문은 `{ "post": "/posts/글주소/", "id": "임의 UUID" }`입니다. 방문 ID 저장과 누적 수 증가는 D1 batch 트랜잭션으로 처리해 동시 요청이 같은 ID를 두 번 집계하지 않습니다.

## 로컬 확인과 운영 반영

로컬 미리보기는 기존 댓글 서버의 로컬 D1에 `0002_pageviews.sql` 마이그레이션을 적용하여 확인합니다. localhost 페이지가 운영 API를 가리키는 경우에는 조회만 하고 운영 조회수를 올리지 않습니다.

운영 반영은 사용자가 푸시·배포를 요청했을 때만 합니다. 순서는 **운영 D1 마이그레이션 → Worker 배포 → 블로그 배포**이며, 기존 댓글 데이터는 유지합니다. 새 DB나 비밀값은 필요하지 않습니다. Workers/D1의 기존 무료 한도를 함께 사용하며 요금제를 변경하지 않습니다.

## 오른쪽 패널 방문자 통계

홈·카테고리에서는 최근 업데이트·인기 태그 아래에, 글 페이지에서는 **Contents(목차) 아래에** 오늘 방문자·어제 방문자·누적 방문 수를 표시합니다. 글의 목차와 통계는 같은 영역에서 함께 스크롤되며, 목차가 없는 글도 오른쪽 패널 아래에 통계를 표시합니다. 홈·카테고리·글 페이지를 이동해도 같은 브라우저는 서버의 한국 시간(KST) 기준 하루 한 번만 집계합니다. 누적 방문은 날짜별 방문자 수의 합이며, 전 기간의 고유 인원 수가 아닙니다. 글 상단 조회수와는 별도입니다.

`visitor_stats.enabled`로 표시와 집계를 켭니다. `visitor_stats.endpoint`가 비어 있으면 `pageviews.endpoint`, `comments.anonymous.endpoint` 순으로 API 주소를 공유합니다. 모바일에서는 기존 테마처럼 오른쪽 패널이 숨겨지지만 방문 집계는 계속됩니다.

브라우저에는 API별 임의 UUID 하나를 저장합니다. 서버에는 비밀값과 날짜를 포함한 HMAC-SHA-256 해시만 저장하므로 DB에 원래 UUID·IP·방문 경로가 남지 않고 날짜 사이의 방문자를 연결하지 않습니다. 중복 방지 해시는 오늘과 어제만 보관하며 일별 수와 누적 수는 유지합니다. 저장소 삭제·다른 브라우저·최초 동시 탭 등의 상황에서는 실제 사람 수와 차이가 날 수 있습니다.

`GET /visitors`는 `{ date, timezone, today, yesterday, total }`을 읽고, `POST /visitors`에 `{ "id": "임의 UUID" }`를 보내면 오늘 방문을 등록한 뒤 같은 통계를 반환합니다. 중복 방지 항목과 오늘·누적 카운터를 하나의 D1 batch에서 갱신해 재시도·동시 요청의 중복이나 일부 갱신을 방지합니다. 새 방문 요청은 댓글·조회수와 분리된 분당 60회 제한을 사용합니다.

Do Not Track·Global Privacy Control·브라우저 저장소 차단 시 통계는 읽기만 합니다. 숨겨진 탭은 실제 표시된 뒤 집계하고, localhost에서 운영 API를 쓰는 미리보기는 운영 통계를 올리지 않습니다. 연결 실패 시 임의 값 대신 `—`와 안내를 표시합니다.

방문자 통계에는 `0004_visitors.sql` 마이그레이션이 필요합니다. 집계는 실제 운영 배포 후부터 시작하며 과거 방문자는 복원하지 않습니다. 로컬 DB와 운영 DB는 분리하며 **운영 마이그레이션·배포·푸시는 사용자의 요청이 있을 때만** 진행합니다.
